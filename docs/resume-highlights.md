## 3. 项目要点（动作 → 系统能力 → 价值 → 证据）

### 3.1 自研代码库学习 Agent

- **建议写法**：独立设计并实现代码库学习 Agent：8 个确定性工具（目录/入口/依赖/imports/签名/搜索/读文件）负责“读代码”，LLM 只负责总结推理，把幻觉风险控制在工具边界内；自研 ReAct 循环，无 LangChain 依赖。
- **事实证据**：`src/tools/` 8 个纯规则工具；`src/agent.py` 自研循环；`src/prompts.py` 提示词约束“每个结论必须带完整相对路径:行号”。
- **个人边界**：单人从零实现，架构与代码原创；产品/评测方法参考了开源项目思路（方法论借鉴、代码自写）。

### 3.2 反幻觉评测体系（区别于普通代码问答的关键）

- **建议写法**：建设 10 个 GitHub Trending 热门仓库评测集（flask/react/vite/uv/rustdesk 等，覆盖 Python/Go/Rust/TypeScript 与 37~4555 个源码文件的规模跨度）；定义引用精确率、幻觉率、章节覆盖三类指标并脚本化跑分；全量基准评测 10/10 通过、引用精确率 100%、幻觉率 0%。
- **追得下去的细节（面试可讲）**：定位到 uv/vite 等大仓库“报告无引用”的根因不是模型能力，而是超长 README 挤占上下文预算导致核心代码块被截空 → 通过固定块限流 + 核心文件保底预算修复（提交 278f747）。
- **个人边界**：评测仓库为公开项目，指标由自研脚本统计，无外部用户数据。

### 3.3 大仓库分层 + 免费模型自动降级（工程韧性）

- **建议写法**：源码文件 ≥300 自动切换“全局层 + 模块层”上下文组织，monorepo（packages/crates）递归识别模块，保证每个主要模块都有可引用的真实行号；主模型限流（429）时按备用链自动降级到其他免费模型并保持粘性，实测免费模型全链路可用。
- **事实证据**：`src/context.py` 大仓库分层；`src/config.py` 降级链（glm-5.2:free → minimax-m3:free → nemotron-3-super:free）；`src/agent.py` 多轮退避 + 跨模型降级。
- **个人边界**：降级链中的模型为 OpenRouter 免费档，效果随上游可用性波动，已通过重试/降级兜底。

### 3.4 产品化：CLI + Web + MCP Server

- **建议写法**：交付三种形态：CLI（Markdown 报告导出）、Gradio 单页（静态报告 / AI 概览含工具调用轨迹 / 边读边问 / 学习进度勾选清单，本地 JSON 持久化）、MCP Server（11 个工具供 Codex/Claude 等直接调用，覆盖加载仓库→静态分析→AI 报告全流程）。
- **事实证据**：`cli.py`、`app.py`、`mcp_server.py`（mcp≥2.0 SDK，stdio 链路测试 `tests/mcp_smoke.py`）；进度存储 `src/progress.py`（`~/.codebase-navigator/progress.json`）。
- **个人边界**：面向个人学习场景的轻量产品，尚无多用户/账号体系（符合 MVP 边界）。

### 3.5 苏格拉底带读 Agent（对话式判定，产品核心差异）

- **建议写法**：实现第二个 Agent——「苏格拉底带读陪练」：先产出 RoadMap 认清全程，再按步骤带读；它不是自由聊天，而是带状态机的教学循环（阅读 → 逐问自检 → 可选动手 → 毕业“能讲”关卡）。每一步由 LLM 按「合格回答应包含」判定是否真懂：输出结构化 JSON（mastered/comment/follow_up），未覆盖就换角度追问，覆盖才解锁下一步；途中可自由提问答疑且不打断进度，也可用 `画图：主题` 按需生成局部图辅助理解。
- **事实证据**：`src/tutor.py`（CLI `TutorSession` 与 Web `WebTutor` 共用同一套判定提示词与 JSON 解析）；验收标准 = 能复述 + 能讲（动手是加分项、可跳过）。
- **带读记忆（Learning Agent 最小闭环）**：`src/tutor_memory.py` 把“进度”从手勾清单升级为 Agent 判定结果——完成一步 = 苏格拉底自检通过，落盘 `~/.codebase-navigator/tutor_memory.json`；下次点「开始带读」从上次未完成步骤断点续读；某要点被追问到上限仍未覆盖会把该步标 ⚠ 薄弱（RoadMap 可见、续读开场提醒），重学达标后自动清标；「重新生成剧本」按标题快照自动作废旧进度，防错位。Web 端 Tab 05 已接线（`repo_key` 按仓库隔离 + 「清空记忆重学」按钮）。
- **个人边界**：判定仍依赖 LLM 即时判断；记忆闭环目前是“断点 + 薄弱点标注”，尚未做到“按历史掌握度动态推荐下一个文件 / 调路线步长”（列入下一步）。

### 3.6 Mermaid 图渲染层（把“看懂”变成画面）

### 3.7 Agent 行为评测（实测数据 · 2026-09-03）

> 与 3.2 的“报告质量评测”互补：这里测的是 **Agent 行为**——问答任务是否答到金标准文件、是否真实打开过目标文件、有没有幻觉引用、几次工具调用。

- **评测脚本**：`evals/run_agent_evals.py`（支持 `--tasks` 自定义任务集与 `repo_path: self` 本地 dogfood，免克隆）+ 任务集 `evals/tasks.yaml`（flask/requests/gin × 3 问，共 9 任务，带金标准文件与关键符号）+ `evals/tasks_local.yaml`（本项目自测 3 问）。
- **指标**：任务成功率（引用到金标文件且无幻觉引用）、金标文件真实触达率（read/import 过）、幻觉率、平均工具调用数、耗时。
- **首轮自评测实测（本项目 3 任务，GLM-5.2 免费档）**：任务通过 **1/3**，幻觉任务 **0**；平均 **28 次工具调用/问**，单问耗时 1.5–4 分钟。失败根因：Agent 已真实读到金标文件，但 30 次工具调用触顶后“强制收尾”的输出不带 `file:line` 引用（Ask 路径当时没有引用质量闸门）。
- **修复后复测（提交 ab31893）**：Ask 路径加“≥2 条不重复引用”的质量闸门并覆盖强制收尾兜底；同一任务复测 **✅ 通过**，引用到金标 `agent.py` + `tools/__init__.py`，幻觉 0。
- **结论**：行为评测能暴露“读了但没引用 / 过度探索”这类报告质量评测看不到的问题；平均 28–30 次工具调用仍偏高，作为下一个调优点（收尾提示词 / 工具上限）跟踪。
- **待跑**：flask/requests/gin 全量 9 任务（需网络通畅；本次因 GitHub 克隆超时未完成，脚本与任务集已就绪）。

## 6. 面试可能追问与准备点

- 为什么不用 LangChain/LangGraph？→ 学习价值、可控性、简历差异化；框架的 Agent 循环本质也是“模型决定→执行→回传”。
- 怎么防止 Agent 死循环/文本模拟工具调用？→ 工具预算上限、接近上限提醒、伪 XML 检测、质量校验三重收尾。
- 引用精确率 / 幻觉率怎么定义？→ 引用能否唯一解析到真实文件；指向不存在文件的引用才算幻觉；同名文件只警告不计幻觉。
- 为什么概览改成“单次生成”而不是多轮工具调用？→ 大仓库下部分模型会把工具调用输出成文本导致死循环；确定性静态上下文 + 一次总结更稳、更快。
- 大仓库分层怎么做的？→ 文件数阈值 + monorepo 展开 + 噪声目录过滤 + 上下文预算分层。
- 免费模型自动降级怎么做？→ 可重试错误判定（429/5xx/连接）→ 备用模型链 → 成功后粘性记录实际模型。
- MCP 的价值？→ 把分析能力变成标准协议，Codex/Claude/Cursor 都能调；11 个工具 + stdio 测试。
- 评测集怎么保证可信？→ 仓库来自 GitHub Trending 且覆盖多语言多规模；引用解析规则三级匹配（exact/basename/suffix）。

### Agent 岗面试的加分叙事（三句话版本）

1. **工具纪律与反幻觉**：8 个确定性工具负责“读代码”，LLM 只做总结推理，所有结论强制 `file:line` 引用——把幻觉风险控制在工具边界内。
2. **生产韧性**：免费模型 429/过载自动降级 + 粘性；检测“文本假装工具调用”→ 提醒 → 强制收尾；工具预算上限、质量校验不合格重答。
3. **双 Agent 设计**：学习 Agent 产出路线，判定 Agent 用苏格拉底法逐问验证“真懂”（能复述 + 能讲），这是和普通代码问答产品最不一样的地方。
